El usuario trabaja en español y aprueba el avance módulo a módulo («sí, sigue por ahí»); suele aceptar la recomendación propuesta y fijar el orden de lo siguiente.

**Why:** en cada entrega se resumía qué se probó (tests, PDF, MuseScore real) y qué no (botones de la UI a mano), y el usuario siguió confiando y avanzando.
**How to apply:** tras cada bloque informar con honestidad lo verificado y lo no probado, listar límites y pendientes, y proponer el siguiente paso con una recomendación. Preguntar antes de cambios de rumbo (licencias, empaquetado de modelos). Mantener GPL-3 y componentes libres/locales.
